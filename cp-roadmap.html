What is competitive programming?

Competitive programming (CP) is solving precisely defined problems with logic, mathematics, data structures, and algorithms. Your code has to produce the right answer and run within the time and memory limits.

Imagine looking for two numbers that add up to a target in a list of a million numbers. Checking every pair takes about 500 billion comparisons. Finding a way to avoid most of that work is the kind of thinking CP develops.

Why CP?

Problem-solving

Get comfortable reasoning through unfamiliar problems and spotting patterns.

Internships and placements

Build the data structures and algorithms (DSA) skills used in coding assessments and technical interviews.

Contests

Try online rounds on Codeforces, CodeChef, and LeetCode, or work toward team competitions like ICPC.

Better programming habits

Learn to reason about efficiency, handle large inputs, and test edge cases.

Getting started from zero

Pick one language and learn enough to read input, use loops and arrays, and print an answer. C++ is our recommendation if you’re starting fresh. If you’re already comfortable with Java or Python, keep using it.

C++

Fast and widely used in CP. Its Standard Template Library (STL) gives you containers and algorithms for common tasks.

Java

Built-in collections and a good fit if it’s already your main language.

Python

Simple syntax helps you focus on the logic. Pay attention to tight time limits on larger inputs.

Your first submission. Set up a compiler or use an online editor, create an account on CodeChef or Codeforces, and try one easy input/output problem. Use LeetCode for DSA practice and CSES for topic-wise algorithm problems.

How to practice

Repeat this process on a few problems each week. Two or three problems you can explain and solve again are a good practice session.

  1. 1

    Read and trace

    Read the inputs, output, and constraints. Work through a sample and a small edge case by hand.

  2. 2

    Start with brute force

    Find a simple correct approach. Estimate its time and memory use from the constraints.

  3. 3

    Look for an improvement

    Try smaller examples or look for repeated work. After a genuine attempt, use a hint or an editorial if you’re stuck.

  4. 4

    Implement and revisit

    Code the approach yourself, test edge cases, and explain why it works. Revisit it later without the editorial.

The learning path

Start with Phase 1 if you’re new to programming. If you already code, pick the first phase whose goal you can’t yet meet comfortably. Try a beginner contest once you can write and submit simple programs.

  1. Phase 1

    Programming fundamentals

    • Input and output, variables, and data types
    • Conditionals and loops
    • Functions
    • Arrays and strings
    • Basic recursion

    Goal. Solve simple programming problems independently.

  2. Phase 2

    Your CP toolkit

    • Time and space complexity and Big-O notation
    • Sorting and searching
    • Built-in libraries such as C++ STL and Java Collections
    • GCD, LCM, and prime numbers

    Goal. Use constraints to explain why one solution is more efficient than another.

  3. Phase 3

    Essential problem-solving techniques

    • Prefix sums and difference arrays
    • Two pointers
    • Sliding window
    • Binary search and binary search on the answer
    • Frequency counting and hashing

    Goal. Recognize common patterns and improve brute-force solutions.

  4. Phase 4

    Algorithmic thinking

    • Greedy algorithms
    • Bit manipulation
    • Number theory and modular arithmetic
    • Recursion and backtracking
    • Basic combinatorics

    Goal. Develop efficient approaches and explain why they work.

  5. Phase 5

    Data structures

    • Stacks and queues
    • Linked lists
    • Sets and maps
    • Priority queues and heaps
    • Trees and binary search trees

    Goal. Choose a data structure based on the operations a problem needs.

  6. Phase 6

    Graphs and dynamic programming

    • Graph representation
    • Breadth-first and depth-first search (BFS and DFS)
    • Shortest paths with Dijkstra’s algorithm
    • Introduction to dynamic programming (DP)
    • One- and two-dimensional DP
    • Knapsack, longest increasing subsequence (LIS), and common DP patterns

    Goal. Model problems as paths or states and reuse solutions to overlapping subproblems.

  7. Phase 7

    Advanced competitive programming

    • Disjoint set union (DSU)
    • Minimum spanning trees
    • Fenwick trees and segment trees
    • Advanced dynamic programming
    • String algorithms (KMP and Z-algorithm)
    • Lowest common ancestor (LCA)
    • Advanced graph algorithms

    Goal. Build the toolkit for harder rated contests and competitions such as ICPC.

When to move on. Use the goal on each card as a checkpoint. Try applying the topic to an unfamiliar problem before moving ahead.

How to use a sheet

Understand the brute-force approach, look for a better one, and work toward an optimal solution where possible. For each approach, explain why it works and analyze its time and space complexity. Alongside the sheet, practice on Codeforces, CodeChef, or CSES to apply those ideas in different settings.

Contests and ratings

Try one contest a week when your schedule allows. If you miss a round, try a virtual contest. Follow the contest’s rules on outside assistance, and count every problem you solve independently as progress.

PlatformWhere to start
CodeforcesDiv. 4 and Div. 3 rounds for contest-style problem-solving.
CodeChefStarters contests with problems of varying difficulty.
LeetCodeWeekly and Biweekly contests for DSA and interview-style problems.
AtCoderAtCoder Beginner Contests (ABC) for algorithmic practice.

How ratings work

Your rating may go up or down after a rated round depending on your performance. Look at your progress across several contests, including which problems you can now solve independently.

Upsolve after the contest

Pick a problem you missed and try again without the clock. If you’re still stuck, read the editorial, explain the idea in your own words, and implement it yourself.

Weekly post-contest discussions

We’ll meet each week to go through contest problems, compare approaches, and discuss optimizations. We’ll also share practice problems, resources, and tips in the CP group. Ask any question there, even if it feels basic, or share an approach you found interesting.

Track your progress

Use these milestones to check what you can do independently. Work through them at your own pace.

StageWhat you can do
BeginnerSolve basic programming problems, estimate time complexity, and use your language’s built-in libraries.
IntermediateRecognize common patterns, implement multiple approaches, and solve easier contest problems independently.
ProficientChoose algorithms and data structures for unfamiliar problems, optimize your solutions, and solve problems more consistently in contests.
AdvancedCombine graphs, DP, and advanced techniques as you develop your own approaches to harder problems.

Check in with yourself

  • Can I solve a problem that stumped me a month ago?
  • Am I relying less on hints and editorials?
  • Can I explain why my solution works and analyze its complexity?
  • Can I recognize and adapt a familiar pattern in an unfamiliar problem?

Beyond the roadmap

Try ICPC

The International Collegiate Programming Contest is a team competition for university students. Practice past problems with teammates to build your ability to solve together.

Tackle harder problems

Explore advanced DP, graphs, and string algorithms. Gradually increase the difficulty of what you practice on Codeforces or AtCoder.

Use and share what you learn

Apply these skills in interviews, software development, or other CS areas such as AI/ML and cybersecurity. Try explaining a solution to someone else to test your understanding.

Set goals that fit your interests, keep exploring, and bring your questions to the CP group. Coding Club is here to help throughout your journey.
